Redbook-aligned STRATUM infrastructure operating and trust application combining the Spatial model, evidence-backed lifecycle management, STRATUM Chain and Digital Immutable Records (DIRs).

- Product/application: **STRATUM Spatial Verified**

## Current build phase

This repository is being converged to STRATUM Redbook Version 1.0 in the locked dependency order:

1. **P0 — Canonical Trust Foundation**: canonical schemas/terminology, PoVI target, NDIR/MDIR/DIR, PFC/PLC/Genesis, validator registry and portable validator path.
2. **P1 — Platform Convergence**: STRATUM Spatial Verified, Data Room, AI Costing and JARVIS around shared canonical objects and trust semantics.
3. **P2 — Field / Engineering / OT**: OPC UA/edge, Spatial reconstruction, engineering services, QA, safety, commissioning and operations.
4. **P3 — Ecosystem / Scale**: external connectors, Studio/SIR/WASM, certification and sovereign-scale deployments.

The Redbook status vocabulary is mandatory: `IMPLEMENTED`, `PARTIAL`, `PLANNED`, `CONCEPTUALLY_LOCKED`. A concept being locked is not an implementation claim.

## Core flow

Engineering sources → Spatial Compiler → STRATUM Spatial Verified → canonical asset identity → field/commissioning/operations evidence → governed review/HITL → canonical hashing → NDIR/MDIR/DIR path → STRATUM Chain / PoVI finality where implemented → provenance and external verification.

Cryptographic integrity and finality do not by themselves prove physical-world truth. Source provenance, qualified people, instruments, machine state, review and governed approvals remain explicit.

## Privacy boundary

Private Spatial geometry, commercial data, operational data and source evidence stay outside the consensus record unless a governed schema explicitly requires otherwise. Hashes, manifests, opaque canonical references, signatures, timestamps and proof metadata cross the trust boundary as policy permits.
